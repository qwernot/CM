爱快分流教程

约 8 分钟阅读 · DHCP DNS / DNAT / 静态路由
示例爱快网关为 192.168.1.1，CMSingBox 为 192.168.1.20。分流必须同时完成 DNS 和目标路由：DNS 负责产生 FakeIP，静态路由负责把 FakeIP 流量送入 CMSingBox。
不要把 CMSingBox 自身加入代理设备组否则它的订阅、DNS 和节点连接会被再次送回自身，形成环回。

一、CMSingBox 端准备

  1. 确认管理后台、代理控制台和 sing-box 都正常。
  2. 在“设置 → DNS 配置”开启独立 DNS，监听 0.0.0.0:53。
  3. 代理 DNS 上游保持 127.0.0.1:1053；直连 DNS 与直连上游填写 udp://192.168.1.1:53 和 192.168.1.1:53。
  4. 开启透明代理，保存并应用配置。

二、DNS 接入（二选一）

方案 A：DHCP 直接下发（推荐）

进入爱快的 DHCP 服务配置，把 LAN 客户端 DNS 改为 192.168.1.20。终端重新获取租约后，所有 DNS 查询交给 CMSingBox，再由后台的“默认代理/默认直连 + 例外设备”决定分流。

方案 B：只劫持指定设备

  1. 建立名为 proxy_device 的终端分组，加入需要代理的设备 IP 或 MAC。
  2. DHCP 仍下发爱快地址 192.168.1.1。
  3. 在 NAT/端口映射中分别创建 UDP 53 和 TCP 53 的 DNAT：来源为 proxy_device，目标端口 53，转换到 192.168.1.20:53。
TCP 与 UDP 两条都要配置仅劫持 UDP 会导致部分大响应、DNSSEC 或回退到 TCP 的查询绕过分流。

三、建立代理目标组

在爱快“网络设置 → 分流设置 → IP 分组”建立 proxy_cidr，加入 FakeIP 和需要按纯 IP 代理的地址段：

198.18.0.0/15
91.108.4.0/22
91.108.8.0/22
91.108.12.0/22
91.108.16.0/22
91.108.20.0/22
91.108.56.0/22
91.105.192.0/23
149.154.160.0/20
185.76.151.0/24

第一段是 CMSingBox 默认 FakeIP 网段，其余为 Telegram 常用网段，可按实际业务增删。

四、配置端口分流

在“流控分流 → 端口分流”新建规则：

字段建议值
协议TCP + UDP
源地址需要时选择 proxy_device；全设备分流可留空
目的地址proxy_cidr
下一跳/网关192.168.1.20
优先级放在普通多线、运营商和默认分流规则之前

若界面要求分别建立源分流和目的分流，请确保最终命中条件仍是“指定设备访问 proxy_cidr 时走 CMSingBox”。

五、NAT 与防火墙

若爱快不能直接把 LAN 客户端原地址转发到同网段旁路由，请为到 192.168.1.20 的流量开启源 NAT/伪装。防火墙需允许 LAN 到 CMSingBox 的 TCP/UDP 53、TCP 2080、TCP 9090 和被策略路由转发的流量。

六、IPv6 注意事项

没有同步配置 IPv6 分流时，不要通过 DHCPv6/RA 下发其他 IPv6 DNS；否则终端可能优先走 IPv6 DNS，表现为部分域名不经过 CMSingBox。

七、验证与回滚

  1. 终端 DNS 应为 192.168.1.20，或 DNS DNAT 规则计数持续增加。
  2. 代理域名应解析到 198.18.0.0/15，国内直连域名返回真实 IP。
  3. 检查爱快端口分流规则命中数、CMSingBox DNS 监控及代理控制台连接。
  4. 断网时先停用端口分流和 DNS DNAT，并恢复 DHCP DNS 为 192.168.1.1。
